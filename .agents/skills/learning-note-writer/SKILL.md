# Learning Note Writer

IRON LAW: 长期学习笔记必须同时保留“知识结论”和“学习证据”。每个重要知识点都要区分稳定结论、用户卡点、纠偏过程、掌握状态和未验证边界；未通过检验的内容必须标注为“未掌握/待复查”，不得写成已掌握。临时想法、一次性 workaround 和未验证判断不得冒充结论写入长期文档。

## 职责

把教学过程中已经教懂、通过检验或需要持续复习的知识点，按“结论、原理、例子、边界、卡点、纠偏、掌握状态、证据和参考资料”写成可复习的分层文档；不把聊天记录机械转录成流水账。

## 工作流

- [ ] Step 1: 读取 `.agents/skills/references/documentation-layering.md`。
- [ ] Step 2: 判断回写层级：`docs/learning/`、design、decision、stage summary 或不回写。
- [ ] Step 3: 从教学记录提炼本轮目标、范围、知识点、用户实际卡点、纠偏路径、checkpoint、评分、掌握等级和未验证边界。
- [ ] Step 4: 按本 skill 的粒度标准更新文档；每个重要知识点至少形成一个完整记录单元，不只写目录式摘要。
- [ ] Step 5: 将实际使用的外部资料链接放到对应知识点下，并标记下一次复习入口。
- [ ] Step 6: 复核稳定结论、未掌握项、评分和证据没有越界，再输出或写入文档。

## 粒度标准

每个主题总结至少包含以下层次，不能只写知识点目录或教材摘要：

1. **学习目标**：本轮要达到的可验证能力和目标等级。
2. **学习范围 / 非目标**：讲了什么、明确没讲什么，以及不讲的理由。
3. **核心知识点**：每个知识点先写结论，再写原理、最小代码/反例、适用边界和对应资料链接。
4. **过程卡点**：记录用户实际说错、混淆、犹豫、题目条件不足或反馈纠偏的地方；不得把普通正确回答硬写成卡点。
5. **纠偏路径**：说明用什么对比、例子、实验或追问解决了卡点；没有解决就标为待复查。
6. **掌握评价**：分项掌握状态、整体等级（0–6）、评分依据和下一步；评分必须引用 checkpoint、实操或代码证据。
7. **未验证边界**：明确哪些能力本轮没有验证，禁止从课堂答题外推到真实工程能力。
8. **复习入口**：给出下一次应该先复查的最小概念或迁移场景。

单个重要知识点的最低记录单元：

```text
结论 -> 原理 -> 最小例子/反例 -> 适用边界 -> 用户卡点与纠偏 -> 掌握状态 -> 参考资料
```

## 评分与评价规则

- 分项评分可以使用 10 分制，但必须说明评分维度、得分、证据和扣分原因。
- 总体评价必须同时给出：总分或“不评分”、Level 0–6、已掌握、未稳定点、未验证能力和下一步。
- 课堂 checkpoint 通过，只能证明对应知识点达到本轮目标；不能据此给真实项目设计、排错、跨包演化能力打满分。
- 没有实操、编译实验或真实项目迁移证据的工程能力，必须写“未评分”而不是估分。
- 评分和掌握等级不是同一指标：10 分制评价本轮表现细节，Level 0–6 表示可迁移能力阶段。
- 评价必须事实化：引用用户回答、checkpoint 结果、代码实验或明确的未验证范围，不使用空泛鼓励。

## 输出格式

- 回写位置：
- 为什么值得回写：
- 知识点：
- 触发场景：
- 用户卡点：
- 纠偏要点：
- 掌握状态：
- 适用范围：
- 非目标：
- 参考资料：
- 验证结果：
- 未决点：

## 反模式

- 不要把聊天全过程整理成流水账。
- 不要把学习笔记和架构决策混写。
- 不要为了“有产出”强行写文档。
- 不要把没教过、没检验过的知识写成用户已掌握。
- 不要把外部资料只留在对话里；用过就写入对应知识点的参考资料。
