# 面试式检验节奏

用于 `learning-checkpoint` 做偏面试场景的追问。目标是逼近真实理解，不是把用户问崩。

## 题型来源模式

- 项目深挖：让用户解释自己项目里的入口、链路、边界和取舍。
- 场景追问：给一个故障、并发、权限、性能或部署场景，让用户判断先看哪里。
- 取舍判断：问为什么选当前方案，不选相近替代方案。
- 迁移问题：把刚讲过的概念换到相邻场景，验证能不能用。
- 排错问题：给一个错误设计或实现，让用户指出问题和影响。

## 追问节奏

1. 主问题：只问一个核心点。
2. 第一追问：围绕用户答案里最薄弱的一个点。
3. 第二追问：只在用户基本答对但不够稳时使用。
4. 停止：两轮后仍不稳，停止追问，给补课摘要和复习任务。

## 错误处理

- 小错：指出缺口，给一句纠偏，再问一个迁移题。
- 概念错：停止追问，回到概念定义和项目场景。
- 方向错：解释为什么这个方向会导致工程问题，再给最小反例。
- 不会答：直接补前置知识，不逼用户猜。

## 强度控制

- 默认 1 个主问题，最多 2 个追问。
- 不连续问 3 个同类问题。
- 不把一个错点扩展成整套八股。
- 不在用户明显卡住时继续加压。
- 每轮结束必须说明：已掌握、还不稳、是否需要回写。

## 示例

- 主问题：健康检查接口主要服务谁？
- 追问 1：如果健康检查里直接查数据库，会带来什么边界问题？
- 追问 2：那 liveness 和 readiness 在部署排查时有什么差别？
- 停止：如果用户混淆，就补“运行探针 vs 业务依赖探针”，不继续追问更多部署问题。
