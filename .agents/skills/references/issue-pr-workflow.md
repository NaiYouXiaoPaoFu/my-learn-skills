# Issue / PR 精准上下文工作流

这个文件约束 agent 如何接住用户粘贴的 issue、PR、评论或链接。

## 核心规则

- issue/PR 是任务边界，不是背景材料之一；默认内部消化，不复述正文。
- 优先读取 issue/PR 的标题、正文、任务树、验收标准、评论、关联 PR、关联文件和标签。
- 只加载能服务当前 issue/PR 的知识点、代码入口和文档。
- 如果只有链接且无法访问，不猜内容，要求用户粘贴标题、正文、评论或 PR diff 摘要。
- 如果 issue 已经给出精准文件、接口、模块或验收标准，不再扩大范围。

## 粒度判断

### 强粒度

- 目标、背景、任务树、验收标准、相关模块、约束都很明确。
- 适合直接进入：`issue-pr-intake` -> `learn-context` -> `code-path-tracer` / `review-coach`。
- agent 只补必要知识，不重新拆 issue。

### 正常粒度

- 目标和验收标准清楚，但相关文件、风险或知识点需要补齐。
- 适合进入：`issue-pr-intake` -> `learn-context` -> `project-deep-dive`。
- agent 可以补 2 到 5 个子任务，但不能重写整个 issue。

### 过粗

- 同时包含多个业务链路、多个无依赖知识点或多个阶段目标。
- 先输出拆分建议，不直接实现或教学。
- 拆分方式：按业务链路、模块边界、验收标准或学习目标拆。

### 过碎

- 只描述一个技术点，没有业务场景或验收标准。
- 先补“它服务哪个项目链路”，再进入 `concept-teacher`。
- 如果只是单点概念问题，不要强行创建项目切片。

## 上下文提取顺序

1. 标题：提取动词、对象、模块和目标。
2. 正文：提取背景、范围、非目标和约束。
3. checklist：提取可执行任务和验收标准。
4. 评论：提取后续变更、争议、隐藏约束和 review 重点。
5. 链接/文件：只打开或搜索被点名的文件、接口、模块、测试。
6. 标签：判断优先级、类型、领域和是否需要 review。

## 输出约束

- 默认只输出执行摘要，不展示完整 Context Pack。
- 必须输出推荐 `Skill Chain`。
- 必须说明“本轮不加载什么”。
- 必须说明“当前 issue/PR 能否直接执行”。
- 必须保留未确认问题，不用猜测补齐。
- 只有用户明确要求“展开上下文包/列出 issue 内容”时，才展示完整提取字段。

## 不加载什么

- 未被 issue/PR 指向的全项目架构。
- 与验收标准无关的框架百科。
- 无关联历史 issue。
- 未被评论或任务树提到的重构建议。
