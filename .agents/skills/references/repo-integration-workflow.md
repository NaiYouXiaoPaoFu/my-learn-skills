# 仓库级 Skills 集成工作流

用于把本学习 skill kit 接入已有项目仓库。

## 核心原则

- 目标仓库已有 `AGENTS.md` 和 skills 是一等输入，不能覆盖。
- 本仓库的学习规则是补充层，不是替代层。
- 相似 skill 要合并职责，不要并排保留。
- 没冲突的 skill 可以直接加入；有冲突的必须先输出合并方案。

## 扫描顺序

1. 读取目标仓库 `AGENTS.md`，抽取硬规则、禁忌、输出协议和项目特定流程。
2. 读取目标仓库 `.agents/skills/*/SKILL.md` 的正文，抽取 description、IRON LAW、职责、工作流、输出格式和反模式。
3. 对照本仓库 skills，用正文证据判断：同名、相似、互补、缺失。不要只按名称或关键词判断。
4. 生成集成计划：哪些直接复制，哪些需要合成，哪些不加入。
5. 让用户确认冲突项后再写入。

## 相似职责判断

判断相似必须引用正文证据：

- description 是否服务同一类用户动作。
- IRON LAW 是否约束同一类风险。
- 职责段是否承担同一工作。
- 工作流是否有 2 个以上相同阶段或相同输入/输出。
- 目标 skill 是否已经实现本仓库某个 skill 的主要职责。

仅名称相似、都提到 issue/PR、都提到架构或文档，不足以判定相似。

## AGENTS.md 合并方式

- 保留目标仓库原有项目规则和安全约束。
- 把学习规则作为独立小节追加或合并到已有“workflow/skills/learning”章节。
- 重复规则只保留更具体的一条。
- 冲突规则要列出，不擅自裁决。

## 输出要求

- 必须列出“可直接新增”和“需要合并重塑”。
- 必须说明为什么某个 skill 不建议加入，并给出 source/target 正文证据。
- 必须给出合并后应该触发的主入口 skill。
- 不要输出目标仓库全部文件内容，只输出集成判断。
