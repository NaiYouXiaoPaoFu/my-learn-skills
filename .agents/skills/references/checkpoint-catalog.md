# 学习检验题型库

每次只选 1 到 3 个问题。先让用户答，再反馈。用户答错后先补缺口，最多追问两轮。

## 概念复述

- 用自己的话解释这个概念解决什么问题。
- 说出它在当前项目链路中的位置。
- 说出如果不用它，代码或架构会出现什么问题。

## 对比判断

- Handler 和 service 的边界是什么？
- DTO 和数据库实体为什么不能无脑复用？
- Middleware 和普通函数封装的差异是什么？
- 闭包和回调分别解决什么问题？
- session cookie 和 JWT 在当前项目中各有什么代价？

## 场景判断

- 如果文章发布接口被重复提交，应该在哪一层考虑幂等？
- 如果管理接口跨域请求没有带 cookie，先查哪几个配置？
- 如果列表页变慢，先看 SQL、索引、分页还是缓存，为什么？
- 如果媒体上传失败，主链路应该立即失败还是降级？

## 最小实操

- 画出某个接口从 route 到 response 的链路。
- 写出一个 handler/service/repository 的职责分配表。
- 把一个万能 DTO 拆成两个页面场景 DTO。
- 给一个中间件写出输入、输出、副作用和失败返回。

## 排错判断

- 找出“handler 直接写 SQL”的问题。
- 找出“repository 里判断用户是否有权限”的问题。
- 找出“缓存命中率高所以设计正确”的问题。
- 找出“只靠前端校验输入”的问题。

## 面试式追问

- 从用户刚讲过的项目场景出发，不从孤立八股开始。
- 先问职责边界，再追问失败路径、取舍原因和验证方式。
- 一次只追一个维度，避免把多个问题合成一串。
- 用户答错后先纠偏，再问一个相邻迁移题；不要继续追同类错题超过两轮。
- 如果用户卡在前置知识，停止追问，回到 `concept-teacher` 补课。
