## Purpose

把语言和引擎知识转成可维护的 GDScript 设计，使学习者能控制职责、依赖和复杂度，而不是仅实现一次功能。

## ADDED Requirements

### Requirement: 学习者能划分脚本职责

学习者 MUST 能根据场景组织、脚本职责、数据与逻辑边界选择组合、信号、直接引用或 Autoload，并能解释取舍。

#### Scenario: 拆分玩家与UI
- **WHEN** 玩家状态变化需要驱动多个界面
- **THEN** 学习者能保持职责边界，避免互相持有不必要的节点引用或形成循环依赖

### Requirement: 学习者能进行基础质量改进

学习者 MUST 能遵循 GDScript 命名/格式风格，识别明显的每帧浪费、过早全局化和重复逻辑，并能通过重构保持可观察行为。

#### Scenario: 重构仍保持行为
- **WHEN** 贯穿项目出现重复查找节点和散落配置
- **THEN** 学习者能重构为更清晰的引用/资源设计，并用原有场景行为和解释题验证无回归
