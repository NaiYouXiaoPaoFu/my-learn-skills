## Context

本方案独立承载 GDScript 学习主线。SQLite 已记录 GDScript 主题、知识状态、checkpoint、来源记录，以及已确认的通用学习偏好：不预设前置知识、优先官方资料、讲解结合类比/图示/最小代码、允许示例但不默认代写、不限制单次会话长度。

官方 Godot stable 文档将 GDScript 定义为面向对象、命令式、渐进式类型语言，语法使用缩进且独立于 Python；官方文档同时把节点/场景、信号、静态类型、资源、生命周期和最佳实践分布在不同章节。因此教学不能只按语法章节线性推进，必须在语言概念出现后立即接入 Godot 运行模型。用户当前实测使用 Godot 4.6，教程中的版本相关行为按 4.6 运行结果与对应文档核对。

## Goals / Non-Goals

**Goals:**

- 形成一条可恢复的 12 阶段主线，每阶段产出可运行行为与可解释模型。
- 让用户从“写出语法”进步到“根据需求选择数据结构、生命周期、信号、类型和脚本边界”。
- 用同一个 2D 小游戏纵向承载概念，减少无关环境切换；每次只引入当前目标所需的 Godot API。
- 用预测—运行—解释—变更四步证据判定掌握，不用“看过文章”判定掌握。

**Non-Goals:**

- 不把所有 Godot API 做成百科式课程。
- 不在基础阶段引入其他语言对照、复杂架构框架或高级性能优化。
- 不用复制粘贴完整项目代替用户的设计、调试和口头解释。

## Decisions

### 1. 版本基线：Godot 4.6，版本差异按官方文档核对

用户已报告 Godot 4.6，且最小场景成功运行。课程示例以 Godot 4.x 语法为准；若某项 API 或编辑器行为出现差异，先记录版本并查对应 Class Reference，避免把版本差异误讲成语言规则。

### 2. 主线顺序：语言核心 → 引擎模型 → 协作与质量 → 综合迁移

先用纯脚本小题建立表达式、控制流、函数、集合和类型模型，再放入 Node/Scene。这样能区分“GDScript 语义错误”和“Godot 生命周期错误”；进入节点后，所有代码都同时追踪脚本实例、节点树和数据流。

### 3. 贯穿项目：小型 2D 游戏，不锁定题材

默认使用“可移动角色 + 收集物 + UI 状态 + 信号 + 可配置资源”的小型项目。题材可替换，但验收边界固定：输入、帧更新、状态、节点引用、信号、异步、资源、调试和重构都必须出现。

### 4. 每阶段固定证据协议

1. 预测：用户先说执行结果或设计选择。
2. 最小实操：用户运行或修改不超过当前概念范围的代码。
3. 解释：用户说明变量/节点/信号/生命周期的因果。
4. 迁移：改变一个需求，观察是否能迁移而不是背答案。

连续两轮不稳时回退到更小概念；未通过的内容只记录为未验证或误区。

### 5. API 教学采用“抽象先行、查文档实现”

不要求背诵 Godot 类库。教学先解释 Node、Scene、Resource、Signal、Callable 的职责和关系，再让用户用 Class Reference 查方法签名和生命周期约束。每次引用外部资料都把具体链接交给教学和后续笔记。

### 6. 代码边界：示例用于观察，关键实现由用户完成

可以提供最小可运行片段、故障片段和局部提示；综合项目不直接代写全部实现。需要帮助时优先给行为预测、断点位置、接口约束和下一步实验，而不是整段替换代码。

## Stages

1. 环境与脚本心智模型：Godot 项目、节点、脚本文件、运行入口、注释、缩进、变量、常量。
2. 值、表达式与控制流：基本类型、运算符、if、循环、match、函数和作用域。
3. 数据与引用：Array、Dictionary、字符串、向量、复制/别名、typed collections。
4. 类型与错误：显式类型、推断、Variant、转换、警告、assert、调试器。
5. 对象模型：类、实例、继承/组合、class_name、super、Callable、lambda。
6. 节点与场景：SceneTree、实例化、路径引用、_init/_ready/_exit_tree、生命周期安全。
7. 输入与游戏循环：InputMap、输入回调、_process、_physics_process、delta、角色移动。
8. 信号与异步：声明、发射、连接、解耦、await、Timer、生命周期与取消。
9. 资源与编辑器：Resource、preload/load、@export、资源数据、tool 的边界。
10. 质量与架构：风格、职责、依赖方向、Autoload、场景组织、性能判断、版本控制。
11. 项目实现：按需求拆场景、实现状态/UI/配置、定位和修复预置缺陷。
12. 综合考核：独立变更、解释、调试、重构和迁移。

## Risks / Trade-offs

- **范围过宽：** “完整”按 GDScript 语言 + 完成 2D 脚本闭环定义，不承诺覆盖 Godot 全部系统；后续主题登记而不抢主线。
- **版本漂移：** stable 文档会变化；每阶段记录使用版本和链接，示例发生差异时以当前官方文档为准。
- **只会跟做：** 每阶段必须有迁移题和解释题；不以一次成功运行作为掌握证据。
- **引擎复杂度掩盖语言缺口：** 前五阶段安排小型纯脚本实验，并在错误定位时明确区分解析、类型、运行时和生命周期错误。
- **环境不可用：** 如果暂时无法运行 Godot，可先做语义预测与伪故障分析，但该阶段只能标记为部分验证，不能替代运行证据。

## Open Questions

无必须在批准前解决的设计问题。默认使用 Godot 4.7 stable；用户批准后若其实际版本或目标游戏类型不同，再在当前 change 中做局部调整。
